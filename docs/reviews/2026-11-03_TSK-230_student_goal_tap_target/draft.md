# [Next.js] 生徒の目標カード・目標一覧リンクのタップ領域を広げる

## 概要

生徒画面（スマホ前提）で目標詳細・目標一覧へ移るリンクは、押せる範囲が狭くてスマホで押しにくい。このチケットでは次の 2 つを直す。

- 目標カード: カード全体を押せるようにする
- ホームの「目標一覧」リンク: 見た目を変えずに、押せる範囲を 44px の高さにする

対象: Next.js（frontend）のみ。Rails の変更なし。

## 背景(調査結果)

目標まわりの導線は、文字の部分だけがリンクになっている箇所が多い。

| # | 箇所 | 現状 | 押せる範囲 |
|---|---|---|---|
| 1 | 目標カード（ホーム `features/student/Home/Presenter.tsx` / 目標一覧 `features/student/Goals/Presenter.tsx`） | リンクはタイトルの `Typography component={Link}`（14px・1行）だけ。ステータスのチップ・期限・進捗%・進捗バー・余白を押しても遷移しない | 高さ 約20px（推定。14px の行の高さ） |
| 2 | ホームの「目標一覧」リンク（`Home/Presenter.tsx:71`） | MUI の部品ではなく、`next/link` に `style={{ fontSize: 12 }}` を付けただけ（`sx` は使えない）。余白なし | 高さ 約16〜18px（推定。12px の行の高さ） |
| 3 | 目標カードの編集・削除ボタン | `IconButton size="small"` が 2 つ並ぶ（`gap: 0.25`） | 30px 四方（計算値。MUI の small の padding 5px×2 + アイコン 20px） |

同じアプリの中でも、タスク一覧（`Tasks/Presenter.tsx` の `TaskRow`）、お知らせ一覧、目標詳細・目標編集の「紐づくタスク」の行は、**行全体が `Link`** になっている。作りが違うのは目標カードだけ。目標カードを行ごと `Link` で包めないのは、中に編集・削除ボタン（`<a>` / `<button>`）があるため。リンクの中にボタンを入れると不正な HTML になる。

### 検証済みの前提

- 各箇所のリンクの構造: 上の表のファイル・行のコードを読んで確かめた。
- 目標カードの中のボタン: `Goals/Presenter.tsx` には編集（`IconButton component={Link}`）と削除（`IconButton onClick`）がある。`Home/Presenter.tsx` には編集だけがある。コードで確かめた。
- IconButton の寸法: `node_modules/@mui/material/IconButton/IconButton.js` で small の padding が 5px、`SvgIcon.js` で `fontSize="small"` が 20px であることを確かめた（30px 四方）。
- `ButtonBase` はもともと `position: relative` を持っている（`ButtonBase.js`）。
- カードの sx に `overflow` の指定はない。`overflow: hidden` があるのはホームのタイトル（省略表示用、`Home/Presenter.tsx:123`）と、目標一覧の進捗バーの枠。
- 既存のテストは、リンクをアクセシブルネームで取得している（`Home/Presenter.test.tsx` の `getByRole("link", { name: "<目標タイトル>" })`、`Goals/Presenter.test.tsx` の `getAllByRole("link", { name: "編集" })`、削除ボタンで `onDeleteClick` が呼ばれるテスト）。アクセシブルネームを変えなければ、既存テストは壊れない。

**未検証**（実装時に実画面で確かめる）:

- 押せる範囲の実寸。表の 1・2 は推定値。実装の前後で、スマホ幅（375px）の実画面で DevTools を使って要素のサイズを測る。
- ホームのタイトルの `overflow: hidden` が `::after` を切り取らないか。`::after` の基準になる箱（containing block）はカードなので、CSS の仕様上は切り取られない見込み。
- 編集・削除ボタンは、`zIndex` を付けなくても DOM の順番で `::after` より上に描かれる見込み。ただし確実にするため、`zIndex: 1` は付ける。

## 設計

### 1. 目標カード: stretched link

- カード（`Box`）に `position: "relative"` を付ける。
- タイトルのリンクに、押せる範囲をカード全体に広げる sx を付ける。ホームと目標一覧で同じものを使うので、`stretchedLinkSx` として `app/theme/studentTheme.ts` の `cardSx` の隣に置く。
  ```ts
  // カードの中に押せる要素（ボタンなど）を足すときは、その要素に
  // position: "relative", zIndex: 1 を付けないと、この ::after に隠れて押せなくなる
  export const stretchedLinkSx = {
    "&::after": {
      content: '""',
      position: "absolute",
      inset: 0,
      // カードと同じ角丸にする。"inherit" はタイトルから引き継ぐので 0 になる。
      // 数値の radius.md は sx では theme.shape.borderRadius 倍（56px）になるので、文字列の値を使う
      borderRadius: cardSx.borderRadius,
    },
    "&:focus-visible": { outline: "none" },
    "&:focus-visible::after": { outline: "2px solid", outlineOffset: 2 },
  };
  ```
  - `::after` の角丸をカードと揃えるのは、キーボードで操作したときのフォーカスリングを、角丸のカード全体に 1 本だけ出すため。
  - Home・Goals がそれぞれ自前で持っている `cardSx` を、`studentTheme.ts` の共通のものに置き換えるのは別の関心事なので、このチケットではやらない（値は同じ）。
- 編集・削除の `IconButton` に `zIndex: 1` を付けて、`::after` より上に置く（`position: relative` はもともと持っている）。
- アクセシブルネームはタイトルのまま変えない（スクリーンリーダーの読み上げも、既存テストも変わらない）。

### 2. ホームの「目標一覧」リンク

- 素の `next/link` を `Box component={Link}` に置き換えて、`sx` を使えるようにする。
- 見た目（文字の位置・見出し行の高さ）は変えずに、押せる範囲だけを広げる。負のマージンで相殺する。
  ```ts
  sx={{
    display: "inline-flex",
    alignItems: "center",
    minHeight: 44,
    px: 1,
    mx: -1, // 右端の位置を変えない
    my: -1.5, // 見出し行の高さを変えない
    fontSize: 12,
    color: colors.accent[600],
  }}
  ```
  - 押せる範囲は見出し行の上下に約 11px はみ出す。下の目標カードとの間（見出し行の `mb: 1.5` = 12px）に収まるので重ならないが、余裕は 1px しかない。見出し行の `mb` は 12px 以上を保つよう、実装時にコメントを残す。
  - `::before` を外側に広げる方式は、隣の見出しや下の目標カードと重なるおそれがあるので使わない。

### 利用者への影響（デメリットを含む）

- 良くなること: カードのチップ・期限・進捗バー・余白のどこを押しても詳細に移れる。タスク一覧と同じ操作感になる。
- 変わること: これまでは何も起きなかった、編集・削除ボタンのすぐ外側を押すと、詳細に移るようになる。壊れる操作（削除など）ではないので許容する。
- 変わること: カードの上で長押ししてタイトルの文字を選ぶのがしにくくなる。目標のタイトルをコピーする場面は少ないので許容する。

## 比較した案

| 案 | 採用しない理由 |
|---|---|
| カード全体を `Link` で包む | 中に編集・削除ボタンがあり、リンクの中にボタンを入れると不正な HTML になる。キーボード・スクリーンリーダーでの操作もおかしくなる |
| MUI の `CardActionArea` で包む | 中身は `<button>` なので、同じように中に `IconButton` を入れられない。カードを `Card` に作り替える必要もある |
| カードに `onClick={() => router.push(...)}` を付ける | `<a>` ではなくなるので、長押しのメニュー・新しいタブで開く・プリフェッチが使えない。キーボードで操作するには別の対応が要る |
| 編集・削除をカードの外（詳細画面だけ）に移す | カード全体を `Link` にできるが、一覧から直接編集・削除できなくなる。機能の変更になるので、このチケットではやらない |
| 「目標一覧」リンクに `minHeight: 44` だけを付ける | 見出し行の高さが約 2 倍になり、下の目標カードが約 20px 下にずれる |

## やること

この変更は CSS（重なり順と余白）だけで、jsdom では押せる範囲を確かめられない。このため Red になる単体テストは作れない。既存のテストは回帰防止として残し、検証の本体は実画面の確認で行う。スタイルの値を断定するテストは壊れやすいので書かない。

1. `stretchedLinkSx` を作り、目標一覧（`Goals/Presenter.tsx`）とホーム（`Home/Presenter.tsx`）の目標カードに使う
   - 既存テストが通ること（タイトルのリンクの `href`、編集リンク、削除ボタンで `onDeleteClick` が呼ばれる）
2. 編集・削除の `IconButton` に `zIndex: 1` を付ける（サイズは変えない）
3. ホームの「目標一覧」リンクを `Box component={Link}` にして、押せる範囲を広げる
   - 既存テストが通ること（`getByRole("link", { name: "目標一覧" })` の `href`）
4. 実画面（スマホ幅 375px）で確認し、結果を PR に載せる。完了条件と 1 対 1 で対応させる
   - (a) カードのチップ・期限・進捗バー・余白を押すと、目標詳細に移る（ホーム・目標一覧）
   - (b) 編集・削除ボタンを押すと、詳細に移らずにそれぞれの動作になる。ボタンの縁を押したときも確かめる
   - (c) DevTools で、「目標一覧」リンクの押せる範囲の高さが 44px 以上あることを測る（変更前後の値を載せる）
   - (d) 変更前後のスクリーンショットを比べ、ホームの見出し行と「目標一覧」リンクの文字の位置のずれが 4px 以内である
   - (e) Tab キーでカードにフォーカスしたとき、角丸のカード全体に 1 本だけフォーカスリングが出る
   - (f) ホームの長いタイトルが省略表示（…）のままで、カード全体を押せる

## 完了条件

- ホーム・目標一覧の目標カードは、編集・削除ボタンを除いて、カードのどこを押しても目標詳細に移る（4-a・4-f）
- 編集・削除ボタンを押すと、それぞれの動作になり、詳細には移らない（4-b）
- ホームの「目標一覧」リンクの押せる範囲の高さが 44px 以上ある（4-c）
- 変更前後で、ホームの見出し行と「目標一覧」リンクの文字の位置のずれが 4px 以内（4-d）
- キーボードで操作したとき、カード全体にフォーカスリングが出る（4-e）
- 既存のテストが通る

## 依存

なし。

## 対象外

- 編集・削除ボタン（`IconButton size="small"`、30px 四方）の拡大。44px にすると目標一覧の進捗%が約 28px 左に動き、375px 幅でタイトルの折り返しが増えるため、オーナー判断で今回は見送る。
- 戻るリンク（「目標一覧へ戻る」「目標詳細へ戻る」「目標詳細に戻る」を含む）。同じ作りのリンクが 7 画面（GoalDetail・EditGoal・TaskDetail・EditTask・Unit・AnnouncementDetail・Question）にある。2 画面だけ直すとほかとずれ、共通化するときに書き直しになる。このため、共通の `BackLink` 部品を作って 7 画面まとめて直す別チケットにする。別チケットとして草案を作り、Backlog に起票する（ID: BackLink チケットの起票後に記入）。
- Home・Goals の自前の `cardSx` を `studentTheme.ts` の共通のものに置き換えること。
- 目標以外の一覧（タスク・お知らせ）。もともと行全体がリンクになっている。

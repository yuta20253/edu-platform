## 確かめた事実

`origin/feature/TSK-206_student_analytics_dashboard` を fetch して確認しました。

- `useFetchAnalyticsSummary.ts` の記述は、草案と一致します。
  - `periodKey` を持ち、`refreshing` は `result !== null && result.periodKey !== periodKey` で出しています。
  - 失敗時は `setResult(null)` で前の期間のデータを消します。401 は `/login` へ移動し、そのときは消しません。
  - 422 のときは `error` を立てず、`validationErrors` に入れます。
  - 草案の4点は、コードと矛盾しません。
- `useApiQuery.ts` も、草案と一致します。
  - 失敗時は `setError(true)` だけで、`data` は残ります。
  - `keepPreviousData: false` は「再取得の開始時」に `data` を消す設計です。「失敗したときに消す」のとは違います。草案は矛盾していませんが、見比べるときの論点になります。
  - `refreshing` と `periodKey` に相当するものはありません。
- `useFetchCumulativeAnalytics` は `useApiQuery` を2つ呼びます。gradeAverage と understandingScore は、それぞれ独立して再試行できます。「4つの取得」の数え方は事実と合います。

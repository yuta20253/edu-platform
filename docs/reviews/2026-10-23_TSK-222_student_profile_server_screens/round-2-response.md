# 第2周の対応(UserProfile / EditUserProfile)

第2周の判定: **直せば進めてよい**

| 指摘 | 重大度 | 対応 | 理由・草案のどこを直したか |
| --- | --- | --- | --- |
| 1. 「直接開く」確認では、レイアウトの `redirect` が先に効いて偽の「問題なし」になる恐れ。確認手順を、クライアント遷移と直接入力に分ける | 重要 | 採用 | 未検証表の確認手順を、(1) 通常ページでログイン (2) Cookie を削除 (3) 読み込み直さずに `Link` / `router.push` で遷移 (4) Network で RSC のリクエストを確認、に書き直した。URL の直接入力は「レイアウトの `redirect` の確認」として別項目にした。完了条件にも同じ手順を書いた |
| 2. 未検証表に、事実(401 で例外)と観察(既定のエラー画面)が混ざっている | 重要 | 採用 | 「401 で例外を投げる」は検証済み表にすでにあるので、未検証側は「クライアント遷移で `/profile/edit` に来たとき、その例外に届く」だけに絞った |
| 3. Red コミットの前に、`rejects` のテストが「resolve して失敗」することを確かめる | 軽微 | 採用 | 「Red のコミットの前に、2本が実際に失敗することを確かめる。`redirect` モックが投げる例外を握りつぶさない」と足した |
| 4. 「コストは小さくない」が逆に読める。TSK-216 の行が完了条件にあるのは測りにくい | 軽微 | 採用 | 「コストは小さい。チケットにする理由は次のとおり」に直した。TSK-216 の行を、完了条件から「やること」に移した |

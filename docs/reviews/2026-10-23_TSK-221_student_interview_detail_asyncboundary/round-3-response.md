# 第3周の対応(InterviewDetail)

第3周の判定: **直せば進めてよい**(最終周。文言の直しのみ)

| 指摘 | 重大度 | 対応 | 理由・草案のどこを直したか |
| --- | --- | --- | --- |
| 1. guard の解除が、どの `finally` か曖昧 | 軽微〜重要 | 採用 | 「`refetch` の中で、再試行中なら何もしない。立てて、表示を初期状態に戻し、`try { await fetchDetail() } finally { 下ろす }`。解除は `refetch` の `finally` だけで行い、`fetchDetail` には ref を持ち込まない。表示を戻す処理は、guard を通った1回目だけが行う」と書き直した |
| 2. 「401 で `/login` に遷移し、エラーは出ない」は、現行では失敗する(Red)。生徒に見える改善でもある | 重要 | 採用 | コードで確認した(401 でも `finally` が `loading=false` にし、`interview` は `null` のままなので、リダイレクト前に `ErrorState` が一瞬出る)。回帰防止から外して Red に移し、「利用者に見える変化」にも1行足した。これで、**このチケットの生徒向けの価値は「再試行」と「401 時のエラーの一瞬表示の解消」の2つ**になる |
| 3. 再試行直後のスピナーは、手動で解決できる promise にしないと偽陽性になる | 軽微 | 採用 | テスト計画に1行足した |
| 4. 「取り直しだけ失敗」の準備のモックが複雑で、消化漏れしやすい | 軽微 | 採用 | URL と呼び出し回数で分岐する `mockImplementation` を使うと書いた |

# セルフレビュー観点

`git diff origin/main...HEAD` を以下の観点で確認する。該当しない観点は飛ばしてよい。

## 正しさ
- チケットの受け入れ条件をすべて満たしているか
- 境界値・異常系（空、null/undefined、0件、上限、不正なID、ネットワークエラー）の扱い
- 非同期処理の競合・ローディング／エラー状態の表示漏れ
- Rails: トランザクション境界、コールバックの副作用、マイグレーションのロールバック可否

## セキュリティ
- 認証・認可の漏れ（ログイン必須か、ロール／権限チェックがあるか）
- 他ユーザー・他学校のリソースをIDの差し替えで参照・更新できないか（IDOR。`current_user` 起点のスコープで取得しているか）
- Strong Parameters・入力バリデーション（許可していない属性の一括代入、型・長さ・形式のチェック）
- SQLインジェクション（文字列埋め込みの `where` 等）、XSS（`dangerouslySetInnerHTML`、未エスケープの出力）
- 機密情報（パスワード、トークン、個人情報）がログ・レスポンス・エラーメッセージ・フロントのバンドルに露出していないか
- BFF（Next.js API Route）でのトークン・Cookie の取り扱い、クライアントへの不要なデータ受け渡し
- ファイルアップロード／CSVインポートのサイズ・形式・内容チェック
- 新規ライブラリ導入時の脆弱性・メンテ状況（`npm audit` / `bundle exec bundler-audit`）

## パフォーマンス
- N+1 クエリ（`includes` / `preload` の要否）
- 不要な再レンダリング・重複リクエスト
- ページネーションや件数制限の有無

## テスト
- 追加した振る舞いに対応するテストがあるか（正常系・異常系・権限）
- テストが実装詳細に依存しすぎていないか
- テスト名が振る舞いを説明しているか

## 可読性・一貫性
- 近いディレクトリの既存パターン（Container/Presenter、hooks、BFF ルート、serializer 等）を踏襲しているか
- 命名、不要なコード・コメント・デバッグ出力の残存
- 型定義（`any` の乱用、型の重複）

## CI
- frontend: lint / format:check / typecheck / test が通るか
- rails: rubocop / rspec / brakeman が通るか
